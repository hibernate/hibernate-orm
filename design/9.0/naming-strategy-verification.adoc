== Supported-Strategy Conformance Expansion

Status: approved by Steve. Implementation and validation are complete.

=== Goal And Design

Give each supported strategy a dedicated executable contract:

* `JpaImplicitNamingStrategyComplianceTest`: verify specification-defined names
  using the actual `ImplicitNamingStrategyJpaCompliantImpl` and identity physical naming.
* `StandardImplicitNamingStrategyTest`: verify Hibernate's documented conventions
  using the actual `StandardImplicitNamingStrategy`, including full attribute paths
  and logical table-name composition.

Share mapping fixtures and metadata inspection helpers where useful, but declare
expected names independently. Do not derive expected names from strategy callbacks,
strategy helpers, or the metadata being tested. Both suites must be independently
runnable. Test-method Markdown Javadoc describes intent; JPA cases link the rule
and identify its scope. Common fixtures must not force strategy-dependent results
into a single opaque expectation function.

Retain the existing five-strategy matrix for regression comparisons and deprecated
implementation coverage. Existing callback/provenance tests remain responsible for
custom strategy invocation. A small amount of overlap with the matrix makes the
supported contracts readable on their own; avoid copying whole existing suites.

Alternatives considered: extending only the five-strategy matrix keeps everything
in one place but obscures which assertions express JPA requirements; duplicating
all fixtures for each strategy makes the suites independent but increases drift.
Dedicated suites with shared fixtures and separately stated expectations are preferred.

=== Specification Baseline And Boundaries

The dependency is `jakarta.persistence-api:4.0.0-M7` in `gradle/libs.versions.toml`.
Use the published
https://jakarta.ee/specifications/persistence/4.0/jakarta-persistence-spec-4.0-m4[4.0-M4 specification]
as a versioned prose baseline, checking relevant annotation contracts against the
M7 API sources before recording final rule references. The local published M7
source artifact was checked for Table, Column, JoinColumn, JoinColumns, JoinTable,
CollectionTable, MapKeyColumn, MapKeyJoinColumn, OrderColumn, PrimaryKeyJoinColumn,
SecondaryTable, DiscriminatorColumn, and MapsId. Do not silently treat a
moving nightly document as a pinned baseline. Record any difference or ambiguity
before choosing an expectation.

Start with relationship mapping defaults (section 2.12), identifier treatment
(section 2.15), and the mapping annotation contracts. The published API references
reviewed for this proposal include
https://jakarta.ee/specifications/persistence/4.0/apidocs/jakarta.persistence/jakarta/persistence/joincolumn[JoinColumn],
https://jakarta.ee/specifications/persistence/4.0/apidocs/jakarta.persistence/jakarta/persistence/jointable[JoinTable],
https://jakarta.ee/specifications/persistence/4.0/apidocs/jakarta.persistence/jakarta/persistence/collectiontable[CollectionTable],
https://jakarta.ee/specifications/persistence/4.0/apidocs/jakarta.persistence/jakarta/persistence/mapkeyjoincolumn[MapKeyJoinColumn], and
https://jakarta.ee/specifications/persistence/4.0/apidocs/jakarta.persistence/jakarta/persistence/primarykeyjoincolumn[PrimaryKeyJoinColumn].

Every case must be classified as a specification requirement, an explicitly
provider-defined choice, or a Hibernate extension. In particular, ordinary
`JoinColumn` and `MapKeyJoinColumn` default-name rules are limited to single-column
joins. Do not label implicit composite-join conventions as JPA requirements.
Required explicit declarations, such as secondary-table names, are not missing
implicit callbacks. Generated constraint-name spelling is not assumed to be
specified by JPA. Generator naming has its own strategy and remains outside this slice.

Physical prefixing, inline views, tenant/soft-delete columns, and named SQL types
belong to extension tests. Preserve their existing focused coverage. JPA plus a
custom physical strategy is tested as Hibernate integration, not as a normative
JPA output. No public SPI is introduced by this test expansion. Strategy alias selection is
independent of the conformance assertions.

=== Implementation Sequence And Failure Policy

. Build a rule-to-test checklist from the inventory. Link existing qualifying tests
  and identify concrete gaps before adding fixtures.
. Add the two dedicated suites, common inspection support, and missing default
  cases. Begin with identity physical naming and ordinary/association names.
. Add embedded, identity/inheritance, XML, and quoting cases; retain independent
  extension checks for physical naming and composite defaults.
. For each failure, establish whether it is a naming callback defect, binding/input
  defect, invalid fixture, or ambiguous requirement. Preserve the specification-based
  expectation. Report behavior changes before changing production naming algorithms;
  do not bless current output or hide failures under expected-failure annotations.
. Run both suites, the existing naming matrix and related focused tests. Run the
  core suite after production fixes or broader test changes requiring integration
  validation. Record exact results and unresolved cases.

Completion requires traceable coverage for each applicable inventory row, both
supported implementations exercised without behavioral overrides, independently
specified expected names, and no unresolved normative mismatch concealed by the
matrix. Representative H2 schema creation/use should verify shared joins and derived
identity where metadata spelling alone is insufficient. Do not claim cross-dialect
execution or full Jakarta Persistence certification from naming tests.

=== Approved Findings And Repairs

. With XML persistence-unit `delimited-identifiers`, schema/catalog defaults
  `NamingSchema` / `NamingCatalog` become quoted `namingschema` / `namingcatalog`.
  Quoting is present, but original case is lost. `BindingOptionsImpl` creates
  unquoted default namespace identifiers and `TableBinder` canonicalizes them
  before finalization. Preserve case and requested quoting before canonicalization.
. Standard's embedded-id input omits the `id` attribute path. `ComponentSource`
  constructs the embedded-identifier source with an empty naming prefix. The
  proposed full-path convention expects `id_region`, not `region`.
. Embedded collection inputs retain only their member name in several binders:
  `CollectionIndexBinder` (order and basic map-key columns),
  `ElementCollectionAttributeBinder` (basic element columns), and
  `PluralAssociationAttributeBinder` (target join columns). Thus Standard yields
  `tags_ORDER`, `labels_KEY`, `tags`, and `links_target_pk` for members of `home`,
  despite using `home_tags` for the collection table and full paths for ordinary
  embedded columns. Supply owner-relative paths to the existing strategy methods.

== Purpose and Test Contract

Exercise common mapping fixtures against every currently selectable implicit strategy.
Verify actual boot-model names, rather than calling the same strategy to manufacture
expected results. Separate characterization of existing behavior from Jakarta Persistence
conformance. Historical behavior passing a test does not make it desirable or normative.

`ImplicitNamingStrategyMatrixTest` runs five strategies against identity and transforming
physical naming: `StandardImplicitNamingStrategy`, `ImplicitNamingStrategyJpaCompliantImpl`,
`ImplicitNamingStrategyLegacyJpaImpl`, `ImplicitNamingStrategyLegacyHbmImpl`, and
`ImplicitNamingStrategyComponentPathImpl`. Thus there are five implementations to evaluate,
not just the historical four. The `default` registration selects JPA.

The physical transformation prefixes table and column names with `p_`. Constraint tests
instead prefix each physical constraint/index role independently. This deliberately exposes
physical dependency names being incorporated into newly generated logical names.
Expectations are declared in the tests, independently of strategy helper methods.
Explicit names, quoting, composite correspondence, and names shared by inverse mappings
are checked as well as implicit spelling.

The suite builds metadata and inspects names; it does not execute generated DDL or SQL.
The repeated-embeddable case additionally validates metadata: Standard and component-path must succeed,
while the other strategies must reject the duplicate writable `zip` columns.
That rejection characterizes a mapping requiring overrides, not a defect in JPA naming.

== JPA Conformance Boundary

The project currently uses Jakarta Persistence API `4.0.0-M7`. The published
https://jakartaee.github.io/persistence/latest-nightly/api/jakarta.persistence/jakarta/persistence/JoinColumn.html[4.0 development JoinColumn documentation]
defines default single join names using the relationship (or entity) name and referenced
primary-key column. Such rules must be tested with independently declared expected names.
The moving development documentation is a reference, not a pinned conformance certificate.

Identity-physical cases avoid ambiguity introduced by Hibernate's physical naming extension.
Prefixing cases deliberately characterize that extension and expose the dependency stage
used. Do not infer a JPA requirement for every prefixing result, or change all callbacks
to physical dependency composition just to match one table rule.

The JPA implementation overrides association-table composition and the attribute-path
hook to preserve terminal attribute names. The dedicated supported-strategy suites now
cover alternate relationship ownership, embedded relationship paths, explicit target
column names, and the other rule families recorded above. This completes the approved
naming coverage inventory; it does not establish full Jakarta Persistence certification.

== Approved Strategy Consolidation

The implemented retention decision is:

* Retain `ImplicitNamingStrategyJpaCompliantImpl`, preserving terminal attribute names
  and its existing association-table naming behavior.
* Make Standard use the full component-safe attribute path, including normalization
  of synthetic identifier-mapper and collection path segments. Repeated nested
  embeddables now receive distinct default names. Full paths reduce collisions;
  they do not guarantee uniqueness against arbitrary explicit names or underscores.
* Deprecate legacy-HBM, legacy-JPA, and component-path for removal, since 9.0.
  Keep their current behavior and selector aliases during the deprecation period.
* Emit `HHH90000046` through `DeprecationLogger` once per mapping resolution using
  a deprecated strategy, including subclasses, after programmatic overrides are
  applied. Accepting an unused deprecated configuration must not produce a warning.
* Keep JPA as the default. Standard is opt-in; its qualified embeddable names
  can change schema names, so users must review mappings before switching.
  Component-path and Standard still differ in association-table composition, so
  this is not a promise of identical schemas after replacing the former.

Acceptance: the shared matrix must now validate repeated embeddables under both
Standard and component-path, and preserve terminal-name behavior for JPA and both
legacy strategies. Warning tests cover aliases, class names, class objects,
instances, programmatic supply, subclasses, and effective supported overrides.
