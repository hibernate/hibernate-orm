= Naming Strategy Verification and Retention
:toc2:
:sectanchors:

Status: Steve approved retaining JPA, moving component-path safety into Standard, and
deprecating the other three strategies with runtime warnings. That work is implemented
and validated. This document retains the test contract and outstanding conformance/coverage work. All five registrations remain available; Standard remains the default.

See link:implicit-naming-strategy-proposal.adoc[the replacement contract] and
link:naming-strategy-redesign.adoc[the broader naming redesign].

== Purpose and Test Contract

Exercise common mapping fixtures against every currently selectable implicit strategy.
Verify actual boot-model names, rather than calling the same strategy to manufacture
expected results. Separate characterization of existing behavior from Jakarta Persistence
conformance. Historical behavior passing a test does not make it desirable or normative.

`ImplicitNamingStrategyMatrixTest` runs five strategies against identity and transforming
physical naming: `StandardImplicitNamingStrategy`, `ImplicitNamingStrategyJpaCompliantImpl`,
`ImplicitNamingStrategyLegacyJpaImpl`, `ImplicitNamingStrategyLegacyHbmImpl`, and
`ImplicitNamingStrategyComponentPathImpl`. Thus there are five implementations to evaluate,
not just the historical four. The `default` registration currently selects Standard.

The physical transformation prefixes table and column names with `p_`. Constraint tests
instead prefix each physical constraint/index role independently. This deliberately exposes
physical dependency names being incorporated into newly generated logical names.
Expectations are declared in the tests, independently of strategy helper methods.
Explicit names, quoting, composite correspondence, and names shared by inverse mappings
are checked as well as implicit spelling.

The suite builds metadata and inspects names; it does not execute generated DDL or SQL.
The repeated-embeddable case additionally validates metadata: Standard and component-path must succeed,
while the other strategies must reject the duplicate writable `zip` columns.
That rejection characterizes a mapping requiring overrides, not a defect in JPA naming.

== Observed Differences

For explicit primary tables `owner_table` and `target_table`, entity alias `OwnerAlias`,
and attributes `targets` and `tags`:

[cols="1,2,2",options="header"]
|===
|Strategy |Association table with prefixing physical naming |Collection table with prefixing physical naming
|Standard |`p_owner_table_target_table` |`p_OwnerAlias_tags`
|JPA |`p_p_owner_table_p_target_table` |`p_OwnerAlias_tags`
|Legacy JPA |`p_p_owner_table_p_target_table` |`p_p_owner_table_tags`
|Legacy HBM |`p_p_owner_table_targets` |Uses Hibernate entity name, ignoring the JPA alias
|Component path |`p_p_owner_table_p_target_table` |`p_OwnerAlias_tags`
|===

Component-path currently inherits the JPA variant's association-table composition.
Standard now shares its attribute-path expansion: `home.location.zip` and
`work.location.zip` become `home_location_zip` and `work_location_zip` instead of
both becoming `zip`.

Legacy HBM also omits the referenced-column suffix from ordinary to-one and
association target keys. Legacy JPA uses the mapped table as an owner-key prefix
in cases where the modern variants use the entity name. These are historical
compatibility choices, not additional mapping capabilities.

== Entity Discriminator Naming

The single-table discriminator now defaults to logical `DTYPE` under all five supplied
strategies and becomes `p_DTYPE` under the matrix's prefix physical strategy.
`ImplicitDiscriminatorColumnNamingTest` covers the dedicated callback, annotation and
XML defaults as supplied names, custom quoted names at runtime, physical transformation,
joined-inheritance settings, suppression, formulas, and invalid callback results.
Embeddable discriminator naming has a separate callback.
`ImplicitEmbeddableDiscriminatorNamingTest` reuses the shared five-strategy/two-physical-policy
matrix for direct, nested, collection-element, and nested collection-element defaults.
Its focused tests cover source precedence, input facts, XML, quoting, explicit bypass,
invalid results, logical-name index resolution, and runtime subtype loading.
Any discriminator naming remains a separate role.

== JPA Conformance Boundary

The project currently uses Jakarta Persistence API `4.0.0-M7`. The published
https://jakartaee.github.io/persistence/latest-nightly/api/jakarta.persistence/jakarta/persistence/JoinColumn.html[4.0 development JoinColumn documentation]
defines default single join names using the relationship (or entity) name and referenced
primary-key column. Such rules must be tested with independently declared expected names.
The moving development documentation is a reference, not a pinned conformance certificate.

Identity-physical cases avoid ambiguity introduced by Hibernate's physical naming extension.
Prefixing cases deliberately characterize that extension and expose the dependency stage
used. Do not infer a JPA requirement for every prefixing result, or change all callbacks
to physical dependency composition just to match one table rule.

The JPA implementation overrides association-table composition and the attribute-path
hook to preserve terminal attribute names. A complete rule-by-rule conformance audit remains necessary,
including alternate relationship ownership, embedded relationship paths, and explicit target
column names. The matrix is a regression foundation for that audit, not a claim that the
entire naming implementation is already conformant.

== Further Coverage

The matrix is broad but not exhaustive. Add strategy-matrix cases alongside the remaining
callback migrations, especially implicit composite joins and composite MapsId across all
variants, IdClass, embeddable associations/overrides, table-per-class, XML mappings supported
in 9.0, soft-delete and audit/history columns, and schema/catalog quoting.
Generator storage names remain a separate `ImplicitDatabaseObjectNamingStrategy` concern.
Named SQL types remain deferred and mutation temporary tables remain internal.

Also retain focused callback tests: identical final spelling alone cannot prove that a
callback was invoked, skipped for an explicit declaration, or invoked exactly once.
Database execution and a dialect matrix are separate from these boot-name assertions.

== Approved Strategy Consolidation

The implemented retention decision is:

* Retain `ImplicitNamingStrategyJpaCompliantImpl`, preserving terminal attribute names
  and its existing association-table naming behavior.
* Make Standard use the full component-safe attribute path, including normalization
  of synthetic identifier-mapper and collection path segments. Repeated nested
  embeddables now receive distinct default names. Full paths reduce collisions;
  they do not guarantee uniqueness against arbitrary explicit names or underscores.
* Deprecate legacy-HBM, legacy-JPA, and component-path for removal, since 9.0.
  Keep their current behavior and selector aliases during the deprecation period.
* Emit `HHH90000046` through `DeprecationLogger` once per mapping resolution using
  a deprecated strategy, including subclasses, after programmatic overrides are
  applied. Accepting an unused deprecated configuration must not produce a warning.
* Keep Standard as the default. Its newly qualified embeddable names are an
  intentional schema-name change; users must review mappings before switching.
  Component-path and Standard still differ in association-table composition, so
  this is not a promise of identical schemas after replacing the former.

Acceptance: the shared matrix must now validate repeated embeddables under both
Standard and component-path, and preserve terminal-name behavior for JPA and both
legacy strategies. Warning tests cover aliases, class names, class objects,
instances, programmatic supply, subclasses, and effective supported overrides.

== Consolidation Validation

The full core suite passes after the approved consolidation: 17,832 tests, 1,525 skipped, zero failures or errors.
The matrix covers both supported strategies and all three deprecated variants.
Deprecation tests verify effective-strategy selection and one warning per resolution.
Existing fixtures with native SQL, shared columns, and explicit referenced-column
names now declare their intended column names; default-naming assertions expect full paths.

== Aggregate Container Naming

`AggregateColumnNamingTest` covers terminal defaults across all five supplied strategies,
custom implicit and physical naming, additive quoting, callback input scope and role,
explicit bypass, effective container overrides, invalid results, plural storage,
collection elements, and map keys. It verifies that identical nested member names stay
isolated in separate aggregate containers. JSON runtime cases exercise H2; XML/STRUCT
cases use PostgreSQL dialect metadata without PostgreSQL database execution.

Two expected-failure reproductions remain: the JDBC binding defect tracked by
https://hibernate.atlassian.net/browse/HHH-20913[HHH-20913], and aggregate type restoration
from metadata archives. Both predate this naming migration. The build executes them in
expected-failure validation mode; their successful validation confirms the bugs remain
reproducible and does not count as passing runtime/archive acceptance.

Final commit-cleanup validation: the complete core suite passed with 17,895 tests,
1,525 skipped, and zero unexpected failures or errors. This includes all 22
aggregate naming cases and execution of both expected-failure reproductions.
