= Cascade Processing Specification

Status: Approved Specification

Revision: 1.2

Approved by: Steve Ebersole

Approval date: 2026-08-06

Package-migration amendment approved: 2026-08-07

Revision history::

* `0.1` -- Initial companion specification for immutable entity-rooted cascade
  plans, invocation-local traversal state, metadata-walker compatibility,
  collection-delta integration, staged migration, and conformance testing.
* `0.2` -- Enumerated current built-in action and cascade-point routes, made
  custom `CascadeStyle` behavior part of compatibility, specified a normalized
  differential decision trace, and added requirements and tests for lazy wrapper
  acquisition, collection cascade-point translation, orphan eligibility, dormant
  routes, and action-specific collection iteration.
* `0.3` -- Selected a factory-scoped mapping-metamodel `CascadePlanRegistry` as
  owner of root plans and collection-element subplans, closed the persister
  ownership question, and defined concrete JMH benchmark fixtures, metrics, and
  execution protocol while leaving the route-migration threshold open.
* `0.4` -- Defined one behaviorally independent traversal context per
  `Cascade.cascade()` entry, allowed diagnostic-only parent correlation, retained
  action-specific contexts as the sole cross-invocation cycle/deduplication
  authority, and closed the nested-context question.
* `0.5` -- Kept route profiles in the initial implementation workstream after the
  generic walker, introduced exact built-in `CascadeActionKind` classification,
  required per-node generic fallback for unclassified actions and styles, and
  closed the route-profile question.
* `0.6` -- Kept normalized decision tracing test-only for the initial
  implementation, added no new production diagnostic contract, recorded
  Hibernate Statistics hooks as non-blocking follow-up work, and closed the
  production-diagnostics question.
* `1.0` -- Defined the benchmark review gate, approved the specification for
  implementation, and explicitly deferred collection-delta integration until the
  collection flush specification is approved.
* `1.1` -- Approved the cascade package migration: moved cascade implementation
  to `org.hibernate.cascade.internal`, cascade extension contracts to
  `org.hibernate.cascade.spi`, and the misplaced `CascadePoint` to
  `org.hibernate.engine.spi`; explicitly accepted the resulting narrow source
  and binary incompatibility without legacy package adapters.
* `1.2` -- Corrected the package migration so `CascadePoint` moves with the
  other cascade contracts to `org.hibernate.cascade.spi`.

== Status and Relationship to Other Documents

This document is the approved companion specification for the compiled cascade
architecture proposed by
link:collection-flush-processing.adoc[Collection Flush Processing].  It turns the
approved cascade direction into normative behavior, compatibility requirements,
tests, and migration gates for implementation.

Collection discovery, mutation intent, `CollectionDelta`, queued-operation
normalization, and the collection-facing orphan-projection boundary are specified
by link:collection-flush-processing-spec.adoc[Collection Flush Processing Working
Specification].  If the two specifications appear to conflict at that boundary,
the collection specification owns delta production and validity while this
specification owns cascade consumption and fallback behavior.

The completed specification progression is:

[source]
----
Working Specification
  -> Development-team review
  -> Approved Specification
  -> Implementation
----

Steve Ebersole approved this specification and authorized implementation on
2026-08-06.

== Scope

This specification covers:

* compilation and ownership of immutable cascade mapping structure,
* entity-rooted plans and reusable collection-element subplans,
* invocation-local cascade traversal state,
* action- and cascade-point-sensitive runtime filtering,
* preservation of association order, lazy behavior, orphan timing, and database
  cascade behavior,
* compatibility with built-in and custom `CascadingAction` implementations,
* integration with valid collection-delta orphan projections,
* diagnostics, migration, conformance testing, and performance evaluation.

== Non-Goals

This revision does not specify:

* changes to public cascade mapping semantics,
* changes to the `org.hibernate.event.spi` event contracts,
* collection mutation decomposition or action-queue representations,
* a public SPI for cascade plans or traversal contexts,
* generated bytecode for cascade traversal,
* replacement of action-specific cycle contexts such as `PersistContext`,
  `MergeContext`, or `DeleteContext`,
* mandatory precompiled route masks for built-in actions,
* removal of the metadata walker before parity gates are satisfied.

== Terminology

Cascade plan::
An immutable descriptor of stable cascade-relevant mapping structure rooted at
an entity mapping.  _Compiled_ means transformed into this descriptor at
`SessionFactory` bootstrap or equivalent mapping-model initialization; it does
not mean generated bytecode.

Cascade plan node::
A stable descriptor for a basic/component boundary, to-one association, or
collection-valued association, including the mapping facts needed to decide and
perform runtime traversal.

Collection-element subplan::
Reusable stable structure describing traversal relative to collection elements.
It is referenced by an entity-plan collection node and is not an independently
invocable cascade root.

Traversal context::
Mutable, invocation-local state used while walking one entity-rooted plan.

Metadata walker::
The existing traversal which repeatedly interprets the persister's parallel
property metadata while cascading.

Compiled walker::
Traversal of a cascade plan using a traversal context and runtime action filters.

Decision trace::
A test-only ordered record of node consideration, value resolution, traversal,
action invocation, lazy-state decision, and orphan handling used to compare the
metadata and compiled walkers.

Route profile::
An optional precomputed capability mask for a known built-in cascade action.  A
route profile is an optimization and does not replace the generic runtime path.
The initial implementation workstream includes profiles which pass their parity
and benchmark gates; any route not yet proven continues to use generic filtering.

Cascade action kind::
An internal classification resolved once at cascade entry by exact identity of a
known `CascadingActions` singleton.  An unknown or custom action has no built-in
kind and always uses generic filtering.

Cascade plan registry::
An internal, factory-scoped, mapping-metamodel service which compiles, owns, and
looks up entity-rooted cascade plans and reusable collection-element subplans by
persister identity.  It is not a public persister SPI.

Normalized decision trace::
A decision trace containing semantic paths, mapping and runtime classifications,
predicate results, value-resolution decisions, action invocations, and orphan
decisions, but excluding compiled-node identity and other walker-specific
implementation details.  Normalization allows the metadata and compiled walkers
to be compared directly.

== Proposed Runtime Model

[source]
----
SessionFactory bootstrap
  -> compile entity-rooted CascadePlan
  -> CascadePlanRegistry caches plan by EntityPersister identity
  -> CascadePlanRegistry optionally caches collection-element subplans by
     CollectionPersister identity

Cascade.cascade(...)
  -> select root plan
  -> create CascadeTraversalContext
  -> apply root guards
  -> visit nodes in mapping order
  -> filter for CascadingAction and CascadePoint
  -> resolve value only when required
  -> perform association/component/collection/orphan behavior
  -> restore scoped context state
----

The mapping metamodel's `CascadePlanRegistry` coordinates root-plan and reusable
subplan lookup.  The compiled walker coordinates traversal.  The active
`CascadingAction` remains responsible for action-specific applicability,
iteration, cycle handling, and the operation performed on a selected child.

== Plan Compilation and Ownership

[[CPS-PLN-001]]
`CPS-PLN-001`:: Hibernate MUST compile stable cascade mapping structure into an
immutable entity-rooted cascade plan once per distinct `EntityPersister` identity
during `SessionFactory` bootstrap.

[[CPS-PLN-002]]
`CPS-PLN-002`:: Cascade entry MUST remain entity-rooted.  A collection persister
MUST NOT own an independently invocable entity-root cascade plan.

[[CPS-PLN-003]]
`CPS-PLN-003`:: An entity-plan collection node MAY reference a reusable
collection-element subplan owned by the factory-scoped `CascadePlanRegistry` and
keyed by `CollectionPersister` identity.

[[CPS-PLN-004]]
`CPS-PLN-004`:: An entity-plan collection node MUST retain its owner-property
facts, including value access, root-relative path, cascade style, foreign-key
direction, logical one-to-one or orphan policy where applicable, and collection
role.

[[CPS-PLN-005]]
`CPS-PLN-005`:: A reusable collection-element subplan MAY retain only stable
collection-side and relative element-traversal structure.  It MUST NOT replace a
child entity persister's root plan.

[[CPS-PLN-006]]
`CPS-PLN-006`:: A cached plan or subplan MUST NOT retain entity instances, session
instances, persistence-context state, collection wrappers, collection contents,
or invocation-specific action state.

[[CPS-PLN-007]]
`CPS-PLN-007`:: Plan nodes MUST preserve mapping property order, component order,
complete root-relative paths, association classification, and every stable fact
required to reproduce metadata-walker decisions.

[[CPS-PLN-008]]
`CPS-PLN-008`:: Compilation MUST NOT encode a runtime-sensitive decision as an
unconditional skip unless parity tests prove that the decision is invariant for
every supported action and cascade point represented by that route.

[[CPS-PLN-009]]
`CPS-PLN-009`:: A generic plan MUST retain one ordered node or equivalent generic
fallback entry for every mapped property considered by the metadata walker,
including basic, component, entity, collection, and `AnyType` properties.  It
MUST NOT assume that a custom action's `appliesTo()` behavior matches a built-in
action.

[[CPS-PLN-010]]
`CPS-PLN-010`:: A plan node MUST retain the mapped `CascadeStyle` or an equivalent
runtime reference capable of preserving `doCascade()`, `reallyDoCascade()`, and
`hasOrphanDelete()` behavior.  Compilation MUST NOT replace an externally
registered style with a built-in style classification unless equivalence is
explicitly guaranteed by that style's contract.

[[CPS-PLN-011]]
`CPS-PLN-011`:: Plan compilation MUST occur after all entity and collection
persisters have been registered and their mapping-model references are resolvable.
Aliases which resolve to the same `EntityPersister` MUST NOT cause duplicate root
plans.  An invalid or incomplete plan MUST fail `SessionFactory` bootstrap rather
than fall back silently at runtime.

[[CPS-PLN-012]]
`CPS-PLN-012`:: The `CascadePlanRegistry` MUST be factory-scoped and immutable for
runtime lookup after bootstrap.  It MUST remain internal and MUST NOT require a
public cascade-plan accessor on `EntityPersister` or `CollectionPersister`.

[[CPS-PLN-013]]
`CPS-PLN-013`:: A plan MAY retain route-profile data for an exact built-in
`CascadeActionKind`, cascade point, and node.  Profile data MUST be derived only
from stable mapping and factory facts and from style/action combinations whose
equivalence to generic predicates is covered by differential tests.

== Traversal Context

[[CPS-CTX-001]]
`CPS-CTX-001`:: Each entity-root cascade entry MUST create or derive one
invocation-local, thread-confined traversal context.

[[CPS-CTX-002]]
`CPS-CTX-002`:: The traversal context MUST carry the active `CascadingAction`,
`CascadePoint`, session, action-specific context value, root identity, current
parent, current plan node, and current attribute path.

[[CPS-CTX-003]]
`CPS-CTX-003`:: When applicable, the traversal context MAY also reference the
active collection flush context and MAY collect diagnostic counters and trace
state.

[[CPS-CTX-004]]
`CPS-CTX-004`:: Parent, node, path, and persistence-context child/parent changes
MUST use scoped restoration.  Normal return and exceptional exit MUST restore
the state visible to the caller.

[[CPS-CTX-005]]
`CPS-CTX-005`:: A persister, mapping-metamodel service, session, or persistence
context MUST NOT retain a completed traversal context.

[[CPS-CTX-006]]
`CPS-CTX-006`:: A generic traversal visited set MUST NOT suppress cascades unless
the corresponding `CascadingAction` contract explicitly permits that behavior.
Existing action-specific contexts remain authoritative for cycle and duplicate
suppression.

[[CPS-CTX-007]]
`CPS-CTX-007`:: A nested event-driven `Cascade.cascade()` entry MUST create a new
behaviorally independent traversal context.  It MUST NOT inherit attribute path,
visited state, current node, current parent, or filtering decisions from the
calling traversal.  It MAY retain an invocation identifier linking it to the
caller solely for diagnostics.  The action-specific context value continues to
be shared where the existing action contract requires it.

== Compiled Walker Behavior

[[CPS-WLK-001]]
`CPS-WLK-001`:: For the same mapping, runtime state, action, and cascade point, the
compiled walker MUST visit the same association values in the same order as the
metadata walker.

[[CPS-WLK-002]]
`CPS-WLK-002`:: The compiled walker MUST preserve existing root guards, including
managed/detached state and enhanced-lazy handling, and MUST preserve the root
fast-path semantics of `CascadingAction.anythingToCascade()`.

[[CPS-WLK-003]]
`CPS-WLK-003`:: Unless an equivalent route decision has been verified for a
built-in action, the walker MUST apply the existing runtime
`CascadingAction.appliesTo()` and `CascadingAction.cascadeNow()` predicates.

[[CPS-WLK-004]]
`CPS-WLK-004`:: The walker MUST resolve an attribute value only when the current
action, cascade point, lazy state, and plan node require that value.

[[CPS-WLK-005]]
`CPS-WLK-005`:: Enhanced lazy attributes MUST be initialized, skipped, or
represented by an uninitialized `PersistentCollection` exactly as under the
metadata walker.  A detached parent MUST NOT cause new unintended initialization.

[[CPS-WLK-006]]
`CPS-WLK-006`:: Collection traversal MUST retain each action's loaded-elements
versus all-elements iterator semantics and the collection's iteration order.

[[CPS-WLK-007]]
`CPS-WLK-007`:: `CHECK_ON_FLUSH` MUST continue to inspect applicable associations
whose cascade style is `NONE` when required by its existing contract.

[[CPS-WLK-008]]
`CPS-WLK-008`:: Foreign-key-direction and `CascadePoint` filtering MUST remain
action-specific and behaviorally equivalent to the metadata walker.

[[CPS-WLK-009]]
`CPS-WLK-009`:: Logical one-to-one replacement and orphan removal MUST retain the
existing before-update versus after-update ordering.

[[CPS-WLK-010]]
`CPS-WLK-010`:: Collection orphan handling and database-cascade relevance MUST be
calculated for the same association direction and at the same traversal point as
under the metadata walker.

[[CPS-WLK-011]]
`CPS-WLK-011`:: Every custom `CascadingAction` MUST remain correct without a
built-in route profile through the generic runtime-filtered path.

[[CPS-WLK-012]]
`CPS-WLK-012`:: An exception MUST identify the same entity information available
today and MUST include the complete compiled attribute path to the failing edge.

[[CPS-WLK-013]]
`CPS-WLK-013`:: The generic walker MUST preserve runtime behavior of custom
`CascadingAction` and custom registered `CascadeStyle` implementations, including
their predicate invocation order and `reallyDoCascade()` distinction for
collection-element traversal.

[[CPS-WLK-014]]
`CPS-WLK-014`:: When traversal enters collection elements at
`AFTER_INSERT_BEFORE_DELETE`, the element traversal MUST observe
`AFTER_INSERT_BEFORE_DELETE_VIA_COLLECTION`, exactly as under the metadata
walker.  Other cascade points MUST pass through unchanged.

[[CPS-WLK-015]]
`CPS-WLK-015`:: The enhanced managed-entity root guard which skips traversal when
the persistence-context entry has no loaded state MUST remain effective before
property traversal begins.

[[CPS-WLK-016]]
`CPS-WLK-016`:: For an uninitialized enhanced lazy collection property on a
managed parent, traversal MUST obtain or associate the corresponding
`PersistentCollection` wrapper when current behavior requires it, even when the
action does not perform on lazy to-one properties.  Obtaining the wrapper MUST
NOT by itself initialize the collection.

[[CPS-WLK-017]]
`CPS-WLK-017`:: Collection orphan discovery MUST preserve current eligibility:
the style and action permit orphan delete, the element type is an entity type, a
persistent wrapper or holder exists, and the collection is not newly
instantiated.  Initialized collections use loaded-state comparison;
uninitialized collections use queued-orphan discovery.

[[CPS-WLK-018]]
`CPS-WLK-018`:: `CHECK_ON_FLUSH` MUST preserve the
`hibernate.unowned_association_transient_check` option, inverse-collection skip,
association-only applicability including associations nested in components, and
database-cascade exception behavior.

[[CPS-WLK-019]]
`CPS-WLK-019`:: Built-in action classification MUST use exact singleton identity
and occur once per root cascade entry.  A custom or otherwise unclassified action
MUST use generic filtering for the entire traversal.

[[CPS-WLK-020]]
`CPS-WLK-020`:: For a classified built-in action, each node MAY use a verified
route profile independently.  A registered custom style, an unverified composed
style, or any node without a proven profile MUST fall back to generic runtime
predicates without forcing the rest of the traversal off its verified profiles.

== Collection-Delta Integration

The requirements in this section refine, but do not replace, `CFS-CAS-*` in the
collection flush specification.

[[CPS-COL-001]]
`CPS-COL-001`:: Flush-time cascade MAY consume orphan candidates from a frozen
collection delta only when that delta represents the same comparison-validity
state currently being inspected.

[[CPS-COL-002]]
`CPS-COL-002`:: Cascade MUST NOT initialize a collection solely to obtain or share
a collection delta or orphan projection.

[[CPS-COL-003]]
`CPS-COL-003`:: Cascade outside collection flush processing, cascade before delta
freezing, and cascade observing a comparison-validity mismatch MUST use the
standalone orphan-discovery path or a newly valid comparison.

[[CPS-COL-004]]
`CPS-COL-004`:: Integration with collection deltas MUST NOT change orphan timing,
queued-orphan behavior, collection iteration behavior, or lazy initialization.

== Diagnostics and Performance

[[CPS-DGN-001]]
`CPS-DGN-001`:: Test diagnostics MUST be able to record, in order, plan nodes
considered and skipped, value-resolution decisions, lazy initialization or skip
decisions, associations traversed, action invocations, and orphan handling.

[[CPS-DGN-002]]
`CPS-DGN-002`:: Failure diagnostics MUST report the complete root-relative path
maintained by the traversal context.

[[CPS-DGN-003]]
`CPS-DGN-003`:: Disabled diagnostics MUST NOT retain traversal state after the
invocation and SHOULD avoid per-node diagnostic allocation.

[[CPS-DGN-004]]
`CPS-DGN-004`:: Metadata-walker and compiled-walker parity MUST be compared using
the same normalized trace vocabulary.  A trace MUST identify at least the root
entity, root-relative path, mapped node kind, cascade style, action, cascade
point, lazy-state decision, value-resolution mode, association-filter result,
collection-iterator mode, action invocation, database-cascade flag, orphan
eligibility/source/timing, and exceptional exit where applicable.

[[CPS-DGN-005]]
`CPS-DGN-005`:: Differential tests MUST run each walker from equivalent fresh
session and entity state.  A decision-only test mode MAY record and suppress
terminal action and orphan side effects after all predicates, lazy decisions,
value resolution, and collection iteration needed for the decision have run.
Separate integration tests MUST execute real built-in actions and verify their
observable effects.  Decision-only mode MUST NOT be enabled in production.

[[CPS-DGN-006]]
`CPS-DGN-006`:: The initial implementation MUST NOT add a new public cascade
diagnostic event, listener, monitor span, or retained production counter as part
of this specification.  Existing trace logging remains available.  A later
Statistics integration MAY be designed separately without changing walker
semantics.

[[CPS-PRF-001]]
`CPS-PRF-001`:: Benchmarks MUST compare metadata and compiled traversal for plan
nodes considered, metadata properties scanned, property-value resolutions,
attribute-path allocations, total temporary allocation, and execution time.

[[CPS-PRF-002]]
`CPS-PRF-002`:: Built-in route profiles MUST NOT replace generic predicates until
benchmarks demonstrate useful savings and the corresponding decision-trace matrix
proves parity.

[[CPS-PRF-003]]
`CPS-PRF-003`:: `CascadeTraversalBenchmark` MUST compare metadata and generic
compiled walkers for at least these plan shapes:

* root fast-path rejection for entities with no applicable cascade work,
* wide sparse mappings with 16, 64, and 256 properties and few associations,
* dense mappings with to-one associations at most property positions,
* nested component paths of depth 1, 4, and 8,
* collection-heavy mappings with empty, 10-element, and 100-element collections,
* enhanced loaded and unloaded association attributes,
* built-in `PERSIST`, `REMOVE`, `MERGE`, and `CHECK_ON_FLUSH` routes, and
* the generic custom-action/custom-style route.

[[CPS-PRF-004]]
`CPS-PRF-004`:: Approval benchmark runs MUST use JMH with at least three forks,
ten warmup iterations, and twenty measurement iterations.  They MUST report
average time and GC allocation per operation and preserve machine, JVM, heap,
fork, iteration, and profiler settings alongside raw results.

[[CPS-PRF-005]]
`CPS-PRF-005`:: Each fixture MUST run paired metadata-walker and generic
compiled-walker variants from equivalent prebuilt mapping and runtime state.
Setup, database access, and terminal cascade side effects not intrinsic to the
walker comparison MUST be excluded from the measured operation or held equivalent
between variants.

The benchmark suite is required.  The numeric regression threshold which gates a
production-route switch is defined by `CPS-PRF-006`.

[[CPS-PRF-006]]
`CPS-PRF-006`:: Behavioral parity is an absolute route-migration requirement.  A
statistically supported regression greater than 5% in traversal time or 10% in
allocation MUST be investigated and explicitly accepted before that route is
switched to compiled or profiled traversal.  Smaller measured differences MUST
be recorded but do not block migration.  A profiled route MUST demonstrate a
measurable benefit in at least one workload it targets.  Any accepted exception
and its rationale MUST be retained with the benchmark results.

== Compatibility Baseline

The compiled walker is an internal implementation change.  Compatibility is
defined by observable traversal behavior rather than internal object identity.

[[CPS-COM-001]]
`CPS-COM-001`:: Except for the package relocation explicitly approved by
`CPS-COM-005` through `CPS-COM-009`, existing public and SPI cascade contracts
MUST remain source and binary compatible unless changed by a separately approved
specification.

[[CPS-COM-002]]
`CPS-COM-002`:: The compiled walker MUST preserve action invocation cardinality,
order, lazy-loading effects, orphan effects, transient-reference failures,
database-cascade effects, and persistence-context registration cleanup.

[[CPS-COM-003]]
`CPS-COM-003`:: During migration, the metadata and compiled walkers MAY coexist.
Selection of the compiled walker for a route MUST be gated by the parity coverage
defined in this specification.

[[CPS-COM-004]]
`CPS-COM-004`:: Deprecated or currently dormant built-in actions and cascade
points MUST remain correct through the generic walker while they remain part of
Hibernate's internal or SPI contracts.  Lack of a current production call site
MUST NOT be treated as permission to compile them away.

[[CPS-COM-005]]
`CPS-COM-005`:: Cascade implementation types MUST move from
`org.hibernate.engine.internal` to `org.hibernate.cascade.internal`.  New plan,
compiler, registry, walker, route-profile, and traversal-context implementation
types MUST use the cascade-internal namespace rather than the general engine
namespace.

[[CPS-COM-006]]
`CPS-COM-006`:: `CascadeStyle`, `CascadeStyles`, `CascadingAction`, and
`CascadingActions` MUST move from `org.hibernate.engine.spi` to
`org.hibernate.cascade.spi` without semantic changes to their extension
contracts, built-in singleton identity, registered-style behavior, or predicate
ordering.

[[CPS-COM-007]]
`CPS-COM-007`:: `CascadePoint` MUST move from
`org.hibernate.engine.internal` to `org.hibernate.cascade.spi`.  The enum values
and their meanings MUST remain unchanged.

[[CPS-COM-008]]
`CPS-COM-008`:: Hibernate MUST NOT retain deprecated forwarding interfaces,
adapter enums, duplicate built-in action singletons, or legacy package facades
for the relocated cascade types.  Source consumers must update imports and
existing binaries using the old type descriptors must be recompiled.

[[CPS-COM-009]]
`CPS-COM-009`:: The approved package incompatibility is limited to the relocated
cascade types and signatures which necessarily reference them.  It MUST NOT
change `org.hibernate.event.spi`, mapping semantics, action invocation behavior,
lazy-loading effects, orphan behavior, or unrelated public and SPI contracts.

=== Cascade-style compatibility

The built-in styles are `ALL_DELETE_ORPHAN`, `ALL`, deprecated `LOCK`, `REFRESH`,
`EVICT`, `MERGE`, `PERSIST`, `DELETE`, `DELETE_ORPHAN`, and `NONE`, plus composed
`MultipleCascadeStyle`.  `CascadeStyles.registerCascadeStyle()` also permits an
external `BaseCascadeStyle`.  Both built-in and registered styles remain runtime
participants in the generic path; the plan describes stable mapping structure
and MUST NOT replace their predicates with assumptions derived only from the
built-in list.

== Acceptance Scenarios

=== `CPS-SCN-001`: Nested component traversal

Given an entity whose nested embeddables contain to-one and collection
associations, the compiled walker visits the same values in mapping order and
reports complete root-relative paths.

=== `CPS-SCN-002`: Detached enhanced entity

Given a detached enhanced entity with unloaded association attributes, compiled
traversal makes the same skip/initialize decisions as metadata traversal and does
not introduce unintended lazy initialization.

=== `CPS-SCN-003`: Check-on-flush

Given an applicable transient association with cascade style `NONE`,
`CHECK_ON_FLUSH` inspects it and reports the same transient-reference result as
the metadata walker.

=== `CPS-SCN-004`: Logical one-to-one orphan

Given replacement of a logical one-to-one association, orphan processing occurs
at the same before-update or after-update point selected by existing semantics.

=== `CPS-SCN-005`: Collection orphan projection

Given a valid frozen collection delta, flush-time cascade may reuse its orphan
projection.  Given stale or absent comparison state, cascade uses standalone
discovery without forcing initialization merely to share the delta.

=== `CPS-SCN-006`: Custom cascading action

Given a custom `CascadingAction` with no route profile, generic runtime filtering
visits and invokes the same edges as the metadata walker.

=== `CPS-SCN-007`: Exceptional component descent

Given failure within nested component traversal, the exception identifies the
complete path and every scoped path and persistence-context registration is
restored.

=== `CPS-SCN-008`: Lazy collection wrapper acquisition

Given an enhanced managed parent with an uninitialized lazy collection property,
compiled traversal obtains or associates the same `PersistentCollection` wrapper
as metadata traversal without initializing it, then applies the action-specific
loaded/all/empty iterator behavior.

=== `CPS-SCN-009`: Collection cascade-point translation

Given root traversal at `AFTER_INSERT_BEFORE_DELETE`, direct to-one associations
observe that point while associations reached through collection elements observe
`AFTER_INSERT_BEFORE_DELETE_VIA_COLLECTION`.

=== `CPS-SCN-010`: Registered cascade style

Given an externally registered cascade style whose `doCascade()` and
`reallyDoCascade()` differ for a custom action, compiled traversal invokes those
predicates in the same order and selects the same direct association,
collection-element, and orphan behavior as metadata traversal.

=== `CPS-SCN-011`: Dormant generic route

Given a deprecated built-in action or a cascade point with no current production
call site, a direct generic-walker test produces the same decision trace as the
metadata walker rather than omitting the route from the compiled model.

== Required Test Coverage

[[CPS-TST-001]]
`CPS-TST-001` -- Plan compiler contract::
Unit tests MUST verify immutable structure, mapping order, node classification,
component paths, owner-property facts, collection-element subplan reuse, cache
identity, and absence of entity, session, wrapper, and collection-content
references.

[[CPS-TST-002]]
`CPS-TST-002` -- Differential decision trace::
For every row of the built-in action and cascade-point matrices, the metadata and
compiled walkers MUST produce equivalent ordered normalized traces for node
selection, predicate evaluation, value resolution, traversal, invocation, lazy
handling, database-cascade handling, and orphan handling.  Dormant routes MUST be
exercised by a direct harness.

[[CPS-TST-003]]
`CPS-TST-003` -- Cascade-style matrix::
Tests MUST cover cascade `NONE`, every individual supported cascade style,
`MultipleCascadeStyle`, at least one externally registered style with distinct
`doCascade()` and `reallyDoCascade()` behavior, applicable and inapplicable
cascade points, and both FK directions.

[[CPS-TST-004]]
`CPS-TST-004` -- Nested structure::
Tests MUST cover multiple levels of embeddables containing to-one associations,
collections, null component values, and mixed association kinds.

[[CPS-TST-005]]
`CPS-TST-005` -- Lazy-state matrix::
Tests MUST cover enhanced loaded and unloaded attributes on managed and detached
entities, the enhanced managed-root/no-loaded-state guard, and initialized and
uninitialized collections.  They MUST distinguish lazy to-one fetch, lazy skip,
wrapper acquisition without initialization, and detached-parent skip.

[[CPS-TST-006]]
`CPS-TST-006` -- Collection-state matrix::
Tests MUST cover loaded-elements versus all-elements iteration, queued additions,
queued orphans, inverse and non-inverse collections, collection iteration order,
newly instantiated wrappers, holder-backed collections, entity and component
element types, collection cascade-point translation, and collection-element
subplans.

[[CPS-TST-007]]
`CPS-TST-007` -- Orphan and database-cascade semantics::
Tests MUST cover logical one-to-one replacement, collection orphan delete,
before-update and after-update timing, database `OnDelete` cascade, and
association-direction filtering.

[[CPS-TST-008]]
`CPS-TST-008` -- Traversal-context restoration::
Tests MUST verify path push/pop, current-parent restoration, persistence-context
child/parent cleanup, normal completion, exceptional completion, and absence of
retained invocation state.

[[CPS-TST-009]]
`CPS-TST-009` -- Cycle semantics::
Tests MUST verify that action-specific contexts retain responsibility for cycle
and duplicate suppression and that generic traversal state does not suppress
required cascades.

[[CPS-TST-010]]
`CPS-TST-010` -- Custom action fallback::
A generic custom `CascadingAction` without a built-in route profile MUST pass the
same differential trace and behavior assertions as supported built-in actions.
The test MUST combine the custom action with a registered custom cascade style.
Additional mixed-plan tests MUST verify per-node fallback when a classified
built-in action encounters a registered or unverified composed style.

[[CPS-TST-011]]
`CPS-TST-011` -- Collection-delta boundary::
Tests MUST cover valid orphan-projection reuse, stale projection rejection,
absence of a collection flush context, cascade before delta freezing,
no-forced-initialization, and standalone fallback.

[[CPS-TST-012]]
`CPS-TST-012` -- Diagnostics::
Tests MUST verify enabled decision traces and complete failure paths.  Tests or
allocation measurements MUST verify that disabled diagnostics retain no state
and do not introduce material per-node diagnostic allocation.

[[CPS-TST-013]]
`CPS-TST-013` -- Performance characterization::
Benchmarks MUST record plan-node visits, metadata scans, value resolutions, path
allocations, total allocation, and traversal time for shallow, deeply nested,
wide, and collection-heavy mappings.  `CPS-PRF-003` through `CPS-PRF-005` define
the required fixture matrix and approval-run protocol.

== Implementation and Migration Staging

[NOTE]
====
The stages organize incremental development.  They do not define partial
conformance with the final approved specification.
====

=== `CPS-STG-001`: Traversal context without plan replacement

Introduce `CascadeTraversalContext` while retaining the metadata loop.  Route
existing mutable traversal state through scoped context operations.  Exit
requires `CPS-TST-008`, `CPS-TST-009`, and existing cascade tests to pass.

=== `CPS-STG-002`: Plan model and compiler

Compile and cache immutable entity-rooted plans and reusable collection-element
subplans.  Continue executing the metadata walker.  Exit requires
`CPS-TST-001` and structural diagnostics.

=== `CPS-STG-003`: Differential generic walker

Run the compiled walker in test-only trace mode using generic runtime
`CascadingAction` predicates.  Exit requires exact accepted parity across
`CPS-TST-002` through `CPS-TST-010`.

=== `CPS-STG-004`: Built-in route migration

Switch built-in action/cascade-point routes to the compiled walker only after the
corresponding differential matrix passes.  Preserve the metadata route as a
migration fallback until every supported route has passed.

=== `CPS-STG-005`: Collection-delta integration

Enable orphan-projection reuse only after collection delta freezing and
comparison-validity behavior satisfy the collection flush specification.  Exit
requires `CPS-TST-011` and the orphan portions of `CPS-TST-006` and
`CPS-TST-007`.

=== `CPS-STG-006`: Profiled built-in routes

Resolve exact built-in actions to an internal `CascadeActionKind` and add route
profiles where `CPS-TST-013` demonstrates useful savings.  Every optimized route
retains differential trace coverage, per-node generic fallback, and the generic
custom-action path.  A route which does not pass its parity and benchmark gates
remains on generic filtering without blocking migration of independently proven
routes.

== Approved Decisions

[cols="1,2,3",options="header"]
|===
| Decision | Status | Approved direction

| `CPS-WD-001`
| Approved
| Require immutable entity-rooted plans as the final architecture; allow the
  metadata walker only as a migration and parity reference.

| `CPS-WD-002`
| Approved
| Create one behaviorally independent, thread-confined traversal context per
  `Cascade.cascade()` entry.  Permit diagnostic-only parent correlation, and
  retain action-specific contexts as the sole authority for cross-invocation
  cycle and duplicate semantics.

| `CPS-WD-003`
| Approved
| Use one internal, factory-scoped, mapping-metamodel `CascadePlanRegistry` keyed
  by persister identity for entity-root plans and reusable collection-element
  subplans.  Do not expose plans through public persister SPI methods and never
  treat collection-element subplans as independent cascade roots.

| `CPS-WD-004`
| Approved
| Implement the generic runtime-filtered walker first, then include verified
  built-in route profiles in the initial implementation workstream.  Resolve an
  internal `CascadeActionKind` by exact singleton identity, retain per-node
  fallback for unknown or unverified styles, and keep the fully generic path for
  every custom or unclassified `CascadingAction`.

| `CPS-WD-005`
| Approved
| Gate migration by metadata-versus-compiled decision traces and observable
  behavior rather than by implementation-shape comparison.

| `CPS-WD-006`
| Approved
| Keep the normalized decision trace in test infrastructure for the initial
  implementation and add no new production diagnostic contract.  Consider
  aggregate Hibernate Statistics hooks as non-blocking follow-up work.

| `CPS-WD-007`
| Approved
| Establish `org.hibernate.cascade.internal` for cascade implementation and
  `org.hibernate.cascade.spi` for cascade extension contracts, move
  `CascadePoint` to `org.hibernate.cascade.spi`, and accept the narrowly scoped
  source/binary incompatibility without legacy package adapters.
|===

== Follow-up Work

=== Hibernate Statistics integration

Consider exposing low-cost aggregate cascade information through Hibernate
Statistics after the compiled walker is implemented and measured.  Candidate
aggregates include root cascade invocations, plan nodes considered and skipped,
association values traversed, lazy attributes initialized or skipped, collection
elements visited, and orphan candidates discovered.

This is not required for initial conformance.  Follow-up analysis must determine:

* whether counters belong to factory-level Statistics, session event monitoring,
  or internal diagnostics,
* which aggregates are useful without introducing entity-name, role, path, or
  action high-cardinality dimensions,
* how disabled Statistics avoids per-node allocation and material branching cost,
* whether additions to the public Statistics API require a separate design and
  specification, and
* how compiled and generic walkers report equivalent semantic counts.

== Implementation Authorization and Deferred Scope

The specification is sufficient to implement `CPS-STG-001` through
`CPS-STG-004` and the benchmark-gated `CPS-STG-006` workstream.  The requirements,
compatibility matrices, normalized decision trace, named tests, and benchmark
protocol define the acceptance target for those stages.

The package migration defined by `CPS-COM-005` through `CPS-COM-009` is approved
as the first work item of `CPS-STG-002`.  Its compatibility impact is intentional
and does not authorize other public or SPI incompatibilities.

`CPS-STG-005` and production use of `CPS-COL-*` are explicitly deferred until
link:collection-flush-processing-spec.adoc[Collection Flush Processing Working
Specification] is approved and supplies its stable delta-validity contract.
Until then, cascade retains standalone orphan discovery and MUST preserve the
current behavior described by `CPS-COL-002` through `CPS-COL-004`.

Implementation deviations from this approved specification require disclosure
and approval before they are made.
