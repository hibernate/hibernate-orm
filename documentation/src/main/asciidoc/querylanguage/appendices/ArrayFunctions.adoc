== Array functions and predicates

:ql-array-example-dir: {core-project-dir}/src/test/java/org/hibernate/orm/test/function/array
:ql-function-extras-dir: {doc-main-asciidoc-dir}/querylanguage/extras

The following functions deal with SQL array types, which are not supported on every database.
See <<ql-array-dialect-support,dialect support>> for availability and version profiles,
including <<ql-array-h2-emulation-limits,H2 emulation limits>>.
For Java attribute mappings, see link:{doc-user-guide-url}#basic-single-column-collections[Array and collection mappings] in the User Guide.

=== `array_sort()`

Returns a sorted copy of the array. When called with no optional arguments, elements are sorted in ascending order with `null` elements placed last.
The optional second argument allows specifying descending order, and the optional third argument controls the position of `null` elements.
Returns `null` if the first argument is `null`.

[[hql-includes-predicate]]
=== `includes`

The `includes` predicate tests whether the array on its left contains every element of the array on its right.
It is syntax sugar for <<hql-array-includes-functions,`array_includes()`>> and has the same membership and null semantics.
For example, `tags includes ['hibernate', 'orm']` tests for both values.

[[ql-array-dialect-support]]
=== Dialect support

The following tables describe registered Hibernate implementations, including native SQL and emulation.
A registered function may still have restrictions on clauses, argument types, paths, or null/error behavior; see its description in this appendix.
These tables are an implementation inventory, not the result of executing every function on every database.

The inventory contains 29 functions: `array()`, `array_agg()`, `array_append()`, `array_concat()`, `array_contains()`, `array_contains_nullable()`, `array_fill()`, `array_fill_list()`, `array_get()`, `array_includes()`, `array_includes_nullable()`, `array_intersects()`, `array_intersects_nullable()`, `array_length()`, `array_list()`, `array_position()`, `array_positions()`, `array_positions_list()`, `array_prepend()`, `array_remove()`, `array_remove_index()`, `array_replace()`, `array_reverse()`, `array_set()`, `array_slice()`, `array_sort()`, `array_to_string()`, `array_trim()`, `unnest()`.
`All` and `All other functions` refer to this inventory.
Version profiles without an explicit threshold use the dialect constructor's default; they do not necessarily identify the latest server version.
Azure SQL uses a cloud capability profile rather than a numbered SQL Server release.

[[ql-array-h2-emulation-limits]]
H2 emulates several array operations using an index range with a default maximum of 1,000 elements.
This bound affects correlated `unnest()` over an array column and operations such as `array_position()` and `array_reverse()`.
Longer arrays can produce incomplete results. Registration of these functions does not imply support for arrays of arbitrary length;
this limit applies to the affected emulations, rather than every H2 array operation.
