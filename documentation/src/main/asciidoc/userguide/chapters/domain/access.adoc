[[access]]
==== Attribute access
:example-dir-access: {core-project-dir}/src/test/java/org/hibernate/orm/test/mapping/access
:domain-access-extrasdir: extras

As a Jakarta Persistence provider, Hibernate can inspect entity fields or property accessor methods.
By default, the placement of the `@Id` annotation determines the default access strategy.
When placed on a field, Hibernate uses field-based access.
When placed on the identifier getter, Hibernate uses property-based access.

[IMPORTANT]
====
To avoid issues such as
https://hibernate.atlassian.net/browse/HCANN-63[HCANN-63 - Property name beginning with at least two uppercase characters has odd functionality in HQL], follow the
https://docs.oracle.com/javase/8/docs/api/java/beans/Introspector.html#decapitalize(java.lang.String)[Java Bean specification] when naming properties.
====

<<access-embeddable-types,Embeddable types inherit the access strategy>> from their parent entities.

[[entity-pojo-accessors]]
Strictly speaking, neither Jakarta Persistence nor Hibernate require accessor methods for a persistent field.
However, direct access to a field of an entity from outside the entity instance itself can expose uninitialized state to the application.
All external access to fields of an entity should go through methods or accessor methods of the entity class.

Declare persistent fields as `private` to prevent direct external access.

With field-based access, Hibernate does not treat entity methods as part of the persistent state.
To exclude a field from the entity's persistent state, annotate it with `@Transient` or declare it using the Java `transient` modifier.

[NOTE]
====
Another advantage of using field-based access is that some entity attributes can be hidden from outside the entity.

For example, the data access layer usually does not need to modify the entity's `@Version` field.

With field-based access, this field does not need a getter or setter for Hibernate to perform optimistic concurrency control.
====

When using property-based access, Hibernate uses the accessors for both reading and writing the entity state.
Annotate a getter with `@Transient` if its JavaBeans property should not be persistent.
Business methods and association-management methods such as `addPhone()` and `removePhone()` are not persistent properties and do not require `@Transient`.
