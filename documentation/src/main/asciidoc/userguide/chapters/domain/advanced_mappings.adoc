[TIP]
====
The goal of the `@Synchronize` annotation in the `AccountSummary` entity mapping is to instruct Hibernate which database tables are needed by the
underlying `@Subselect` SQL query. This is because, unlike JPQL and HQL queries, Hibernate cannot parse the underlying native SQL query.

With the `@Synchronize` annotation in place,
when executing an HQL or JPQL which selects from the `AccountSummary` entity,
Hibernate will trigger a Persistence Context flush if there are pending `Account`, `Client` or `AccountTransaction` entity state transitions.
====

[[identifiers-rowid]]
===== @RowId

When an entity is annotated with `@RowId` and the database supports access by row id,
Hibernate can use the row id pseudo-column for CRUD operations from stateful Sessions.
When the row is loaded Hibernate will track the row id and when CRUD operations on that row is triggered it will use that row id as the restriction.  Row id access is the fastest, most efficient was to refer to rows in the database.

[NOTE]
====
Databases known to have row id support include

* Oracle
* H2
* PostgreSQL
* SpannerPostgreSQL
* Some flavors of DB2
====
