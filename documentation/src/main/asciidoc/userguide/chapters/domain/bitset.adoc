For an otherwise unmapped basic type that implements `Serializable`, Hibernate falls back to Java serialization.
Since `BitSet` implements `Serializable`, its default mapping uses this fallback.

The following sections show alternatives to serialization for storing `BitSet` values.

[[basic-bitset-jdbc-type]]
===== Selecting a different `JdbcType`

The custom `BitSetJavaType` maps `BitSet` values to `VARCHAR` by default.
To store the binary data as `VARBINARY`, change `BitSetJavaType#getRecommendedJdbcType`
to return the `VARBINARY` descriptor, or specify a local `@JdbcType` or `@JdbcTypeCode`.

The following examples for specifying the `JdbcType` assume the custom `BitSetJavaType`
is globally registered.

These mappings store values as `VARBINARY` using the `wrap()` and `unwrap()` methods
to prepare the values instead of Java serialization.
