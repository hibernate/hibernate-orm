[IMPORTANT]
====
Jakarta Persistence supports only POJO entity models.
Use POJO entities for portability across Jakarta Persistence providers.
Hibernate also supports dynamic entity models.
====

[[mapping-model-dynamic]]
===== Dynamic mapping models

Persistent entities do not necessarily have to be represented as POJO/JavaBean classes.
Hibernate also supports dynamic models represented by nested `Map` instances at runtime.
These models require mapping files instead of persistent classes.

An entity has one representation within a given `SessionFactory`.
This is a change from previous versions which allowed multiple entity modes for an entity and a choice of which mode to load.
Entity modes can now be mixed within a domain model; a dynamic entity might reference a POJO entity and vice versa.

[NOTE]
====
Dynamic models support rapid prototyping without implementing entity classes.
They lack compile-time type checking, so type errors are detected at runtime.
The mappings can still define a normalized database schema, allowing POJO entity classes to be introduced later.

Dynamic models also support integration use cases.
For example, Envers uses them to represent historical data.
====
