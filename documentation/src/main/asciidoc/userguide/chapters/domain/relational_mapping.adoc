Entity names identify mapped types in queries; table and column names identify database objects.
This section covers explicit mappings, default names, and naming strategies.

[[entity-pojo-mapping]]
==== Entity names and tables

The main piece in mapping the entity is the {jpaJavadocUrlPrefix}Entity.html[`jakarta.persistence.Entity`] annotation.

The `@Entity` annotation defines just the {jpaJavadocUrlPrefix}Entity.html#name()[`name`] attribute which is used to give a specific entity name for use in JPQL queries.

By default, if the name attribute of the `@Entity` annotation is missing, the unqualified name of the entity class itself will be used as the entity name.

[IMPORTANT]
====
Because the entity name is given by the unqualified name of the class, Hibernate does not allow registering multiple entities with the same name even if the entity classes reside in different packages.

Without imposing this restriction, Hibernate would not know which entity class is referenced in a JPQL query if the unqualified entity name is associated with more then one entity classes.
====

[[domain-secondary-tables]]
===== Mapping secondary tables

`@SecondaryTable` maps additional state of the same entity to another table.
The entity retains one identifier; the secondary table is joined to the primary table using that identifier.
This differs from an association to a separate entity with its own lifecycle.
Use `@Column(table=...)` to place an attribute in a declared secondary table.

[source,java,indent=0]
----
include::{root-project-dir}/hibernate-core/src/test/java/org/hibernate/orm/test/mapping/userguide/DomainModelGuideTests.java[tag=guide-columns-secondary]
----

Here, `title`, `price`, and `createdBy` belong to `guide_entry`, while `summary` belongs to `guide_entry_details`.
The primary key of `guide_entry_details` is `entry_id`, joining the identifier column of `guide_entry`.
When `pkJoinColumns` is omitted, the secondary-table primary-key column names default to those of the primary table.
Composite identifiers require the corresponding join columns when overriding these defaults.

Declare multiple secondary tables using repeated `@SecondaryTable` annotations or `@SecondaryTables`.
To place an entire embedded value in a secondary table, see <<embeddable-table,`@EmbeddedTable`>>.
Hibernate's link:{doc-javadoc-url}org/hibernate/annotations/SecondaryRow.html[`@SecondaryRow`] controls optional and owned secondary rows;
row creation and removal should not be assumed identical for every secondary-table mapping.

[[basic-column-annotation]]
==== @Column

Jakarta Persistence defines rules for implicitly determining the name of tables and columns.
For a detailed discussion of implicit naming see <<chapters/domain/naming.adoc#naming,Naming strategies>>.

For basic type attributes, the implicit naming rule is that the column name is the same as the attribute name.
Use `@Column` to override the implicit column name.

[[domain-column-options]]
===== Column options

Besides naming a column, `@Column` describes its schema and participation in writes:

[cols="1,3",options="header"]
|===
|Member |Purpose
|`name` |Overrides the implicit column name.
|`nullable` |Specifies whether the column permits SQL `NULL`; used when generating the schema.
|`unique` |Requests a single-column unique constraint in the generated schema.
|`length` |Specifies the length for column types to which length applies, such as character and binary types.
|`precision`, `scale` |Specify decimal precision and scale for appropriate numeric types.
|`insertable`, `updatable` |Control whether this mapping contributes the column to generated INSERT and UPDATE statements.
|`table` |Selects the table containing the column; the primary table is used by default.
|`columnDefinition` |Supplies a database-specific SQL fragment for schema generation, reducing portability.
|===

These options do not alter an existing database schema unless schema-management tooling is used.
The resulting SQL types and constraints depend on the dialect.
`nullable=false` is not a substitute for Bean Validation or application validation;
Hibernate may perform nullability checks, but a database constraint remains necessary to enforce the rule for all writers.

`insertable=false` or `updatable=false` does not make a Java field immutable.
It excludes that column from the corresponding generated writes through this mapping.
It does not by itself generate a value or arrange for a database-generated value to be refreshed; see <<mapping-generated>>.
For constraints, indexes, defaults, and generated columns, see <<schema-generation>>.

The example in <<domain-secondary-tables>> combines length and decimal precision with an attribute excluded from updates.

[[mapping-quoted-identifiers]]
==== SQL quoted identifiers

To quote an identifier in generated SQL, enclose the table or column name in backticks in the mapping document.
While traditionally, Hibernate used backticks for escaping SQL reserved keywords, Jakarta Persistence uses double quotes instead.

Once the reserved keywords are escaped, Hibernate will use the correct quotation style for the SQL `Dialect`.
This is usually double quotes, but SQL Server uses brackets and MySQL uses backticks.
