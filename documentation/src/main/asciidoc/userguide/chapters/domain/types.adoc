[[mapping-types]]
=== Domain model overview
:domain-types-example-dir-mapping: {core-project-dir}/src/test/java/org/hibernate/orm/test/mapping
:domain-types-extrasdir: extras/types

A https://en.wikipedia.org/wiki/Domain_model[domain model] describes an application's https://en.wikipedia.org/wiki/Problem_domain[problem domain].
Its persistent classes represent the data mapped by the ORM.
Hibernate works best when these classes follow the Plain Old Java Object (POJO) / JavaBean programming model,
but it also supports other representations, such as trees of `java.util.Map` instances.

Hibernate historically used a proprietary XML format to define mappings.
Jakarta Persistence defines annotations and a standard XML format for mappings that are portable across persistence providers.
This chapter uses Jakarta Persistence mappings where possible and Hibernate extension annotations for additional features.

[NOTE]
====
This chapter mostly uses "implicit naming" for table names, column names, etc.  For details on
adjusting these names see <<naming>>.

In the broadest sense, Hibernate categorizes types into two groups:

* <<categorization-value>>
* <<categorization-entity>>

[[categorization-value]]
==== Value types

A value type is a piece of data that does not define its own lifecycle.
It is, in effect, owned by an entity, which defines its lifecycle.

An entity's state is expressed through fields or JavaBean properties termed __persistent attributes__.
The persistent attributes of the `Contact` class are value types.

An association reference is also a value in the containing entity's state, but the referenced entity has its own identity and lifecycle.
For example, an `Order.customer` reference belongs to the order's state; the `Customer` it references is an entity.
Changing or removing the reference does not, by itself, remove the customer.
<<pc-cascade,Cascade operations>> and <<associations-orphan-removal,orphan removal>> can propagate lifecycle operations to the referenced entity when configured.

In this sense, value types include the following categories:

Basic types:: in the `Contact` mapping, all attributes except `name` are basic types. Basic types are discussed in detail in <<chapters/domain/basic_types.adoc#basic,_Basic types_>>
Embeddable types:: the `name` attribute is an example of an embeddable type, which is discussed in detail in <<chapters/domain/embeddables.adoc#embeddables,_Embeddable types_>>
To-one association references:: `@ManyToOne`, `@OneToOne`, and Hibernate's <<associations-any,`@Any`>> attributes hold references to entities. The reference is part of the containing entity's state; its target is an entity type. See <<associations,_Associations_>>.
*Collection* types:: although not featured in this example, collection types are also a distinct category among value types. A collection may contain values or references to entities. Collection types are further discussed in <<chapters/domain/collections.adoc#collections,_Collections_>>

[[categorization-entity]]
==== Entity types

Entities, by nature of their unique identifier, exist independently of other objects whereas values do not.
Entities are domain model classes which correlate to rows in a database table, using a unique identifier.
The `Contact` class is an entity.

Mapping entities is discussed in detail in <<chapters/domain/entity.adoc#entity,_Entity types_>>.
