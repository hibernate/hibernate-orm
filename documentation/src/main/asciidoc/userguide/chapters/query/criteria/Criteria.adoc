[[criteria]]
== Criteria queries
:example-dir-criteria: {core-project-dir}/src/test/java/org/hibernate/orm/test/query/criteria

Criteria queries represent a query using Java objects instead of a query string.
Use the static metamodel to refer to mapped attributes with compile-time type checking.
Generate metamodel classes as described in <<tooling>>.
A `CriteriaBuilder`, obtained from an `EntityManager` or its factory, creates expressions and query objects.
`createQuery(Result.class)` creates a selection query with the specified result type; `createTupleQuery()` creates a tuple query.
Pass the completed `CriteriaQuery` to `EntityHandler.createQuery()` to obtain an executable `TypedQuery`.
The standard `EntityHandler` contract is shared by `EntityManager` and `EntityAgent`.
See <<hql>> for execution, binding, and options.

[[criteria-from]]
=== Roots, joins, and paths

A root identifies an entity type. Joins navigate mapped associations and embeddables;
paths refer to attributes of roots or joins.
Roots and joins implement `From`; their attribute expressions implement `Path`.
A `Fetch` describes association fetching and does not implement `Path`.

[[criteria-from-root]]

Roots define the basis from which all joins, paths and attributes are available in the query.
A root is always an entity type. Roots are defined and added to the criteria by the overloaded __from__ methods on `jakarta.persistence.criteria.CriteriaQuery`:

This example illustrates accessing the query results through the `jakarta.persistence.Tuple` interface.
The example uses the explicit `createTupleQuery()` of `jakarta.persistence.criteria.CriteriaBuilder`.
An alternate approach is to use `createQuery( Tuple.class )`.

The example uses the older `multiselect()` method, just like in <<criteria-typedquery-multiselect-array-implicit-example>>.
The difference here is that the type of the `jakarta.persistence.criteria.CriteriaQuery` was defined as `jakarta.persistence.Tuple` so the compound selections, in this case, are interpreted to be the tuple elements.

The jakarta.persistence.Tuple contract provides three forms of access to the underlying elements:

typed::
  The <<criteria-tuple-example>> example illustrates this form of access in the `tuple.get( idPath )` and `tuple.get( nickNamePath )` calls.
  This allows typed access to the underlying tuple values based on the `jakarta.persistence.TupleElement` expressions used to build the criteria.
positional::
  Allows access to the underlying tuple values based on the position.
  The simple _Object get(int position)_ form is very similar to the access illustrated in <<criteria-typedquery-multiselect-array-explicit-example>> and <<criteria-typedquery-multiselect-array-implicit-example>>.
  The `<X> X get(int position, Class<X> type)` form allows typed positional access; the value must be assignable to the supplied type.
aliased::
  Allows access to the underlying tuple values based on (optionally) assigned alias.
  The example query did not apply an alias.
  An alias would be applied via the alias method on `jakarta.persistence.criteria.Selection`.
  Just like `positional` access, there is an untyped `Object get(String alias)` form and a typed `<X> X get(String alias, Class<X> type)` form.

[[criteria-extensions]]
=== Hibernate Criteria extensions

Hibernate ORM provides extensions to the JPA Criteria API to allow making use of HQL features through the Criteria API.

The `Session` interface gives access to the `org.hibernate.query.criteria.HibernateCriteriaBuilder`,
a subtype of `jakarta.persistence.criteria.CriteriaBuilder`,
through the `Session#getCriteriaBuilder()` method, which is the entry point to the extensions.

The `HibernateCriteriaBuilder` interface offers additional methods, but also provides covariant overridden methods,
which return subtypes of the respective `jakarta.persistence.criteria.CriteriaBuilder` methods return types.
The subtypes are consistently named by prefixing `Jpa` i.e. `Expression` becomes `JpaExpression`.

These subtypes provide additional methods and covariant overrides to ease working with the extensions.

[[criteria-extensions-count-query]]
==== Count query creation

A very common requirement is the creation of a count query based on an existing query.
This can be done by using the `JpaCriteriaQuery#createCountQuery()` method.

For a simple query without `distinct` or grouping, Hibernate replaces the copied selection with `count(*)`.
For more complex queries, it wraps a copy of the original query as a subquery and counts its rows.

`HibernateCriteriaBuilder` exposes HQL extensions through Java methods.
`CriteriaDefinition` provides a convenient construction style for Criteria queries;
see link:{doc-javadoc-url}org/hibernate/query/criteria/CriteriaDefinition.html[`CriteriaDefinition`].
