[[sql]]
== Native SQL Queries
:example-dir-model: {testing-project-dir}/src/main/java/org/hibernate/testing/orm/domain/userguide
:doc-emeddable-example-dir: {core-project-dir}/src/test/java/org/hibernate/orm/test/sql
:extrasdir: extras

You may also express queries in the native SQL dialect of your database.
Use native SQL when database-specific SQL, an existing SQL statement, or a mapping not expressible through HQL is required.
Many window functions and common table expressions are also available in the link:{doc-query-language-url}[Query Language guide].
It also provides a clean migration path from a direct SQL/JDBC based application to Hibernate/Jakarta Persistence.
For calls, see <<stored-procedures>>. For SQL replacing mapped entity operations, see <<sql-crud>>.

[[sql-jpa-query]]
=== Creating a native query using Jakarta Persistence

The standard `EntityHandler.createNativeQuery(sql, Result.class)` creates a typed selection and may infer its mapping from the result class.
`createNativeStatement(sql)` creates a mutation statement.
Both `EntityManager` and `EntityAgent` provide these methods.
A Hibernate `Session` additionally exposes `NativeQuery` mapping and synchronization APIs.
See <<hql>> for common execution, parameters, results, and options.

[[sql-alias-references]]
=== Alias and property references

In most cases, the above alias injection is needed.
For queries relating to more complex mappings, like composite properties, inheritance discriminators, collections etc., you can use specific aliases that allow Hibernate to inject the proper aliases.

The following table shows the different ways you can use the alias injection.
Please note that the alias names in the result are simply examples, each alias will have a unique and probably different name when used.

.Alias injection names
[width="100%",cols="23%,22%,55%",options="header",]
|=======================================================================
|Description |Syntax |Example
|A simple property |`{[aliasname].[propertyname]}`
|`A_NAME as {item.name}`

|A composite property |`{[aliasname].[componentname].[propertyname]}`
|`CURRENCY as {item.amount.currency}, VALUE as {item.amount.value}`

|Discriminator of an entity |`{[aliasname].class}`
|`DISC as {item.class}`

|All properties of an entity |`{[aliasname].*}` |`{item.*}`

|A collection key |`{[aliasname].key}` |`ORGID as {coll.key}`

|The id of a collection |`{[aliasname].id}` |`EMPID as {coll.id}`

|The element of a collection |`{[aliasname].element}`
|`XID as {coll.element}`

|property of the element in the collection
|`{[aliasname].element.[propertyname]}` |`NAME as {coll.element.name}`

|All properties of the element in the collection
|`{[aliasname].element.*}` |`{coll.element.*}`

|All properties of the collection |`{[aliasname].*}` |`{coll.*}`
|=======================================================================

[[sql-named-queries]]
=== Named SQL queries

Named SQL queries can also be defined during mapping and called in exactly the same way as a named HQL query.
In this case, you do _not_ need to call `addEntity()` anymore.

Jakarta Persistence defines the `jakarta.persistence.NamedNativeQuery` annotation for this purpose,
and Hibernate provides `org.hibernate.annotations.NamedNativeQuery` with additional typed execution options, including the following attributes.
Both annotations may be placed on a `package-info.java` or `module-info.java`, which is a convenient location for query declarations not specific to any particular entity.

`flush()`::
	Controls query-triggered flushing using `QueryFlushMode`. The default, `QueryFlushMode.DEFAULT`, follows the current persistence-context flush mode.
`cacheable()`::
 	Whether the query (results) is cacheable or not. By default, queries are not cached.
`cacheRegion()`::
	If the query results are cacheable, name the query cache region to use.
`fetchSize()`::
	A JDBC driver hint for the number of rows to fetch at a time. The driver determines buffering and whether the hint changes database round trips.
	When no fetch size is specified, the driver default applies.
`timeout()`::
	The query timeout (in seconds). By default, there's no timeout.
`comment()`::
	A comment added to the SQL query for tuning the execution plan.
`cacheMode()`::
	The cache mode used for this query. This refers to entities/collections returned by the query.
	The default value is `CacheMode.NORMAL`.
`readOnly()`::
	Whether newly loaded entities should be marked as read-only. The default is `false`.
	Read-only entities remain managed in the persistence context; dirty checking of their simple properties is skipped.
	This option does not change entities already managed by the context. See <<hql-read-only-entities,read-only query results>>.

For named procedure calls, use `@NamedStoredProcedureQuery`; see <<sql-sp-named-query>>.

====

This way, we can imply the global *crm* catalog and *analytics* schema in every JPQL, HQL or Criteria API query.

Hibernate does not automatically qualify table names in native SQL using these defaults.
Unqualified names are resolved by the database using the connection's current catalog, schema,
or search path. When qualification is needed, include it explicitly in the SQL or use the
following Hibernate placeholders to apply the configured default catalog and schema:

{h-catalog}:: resolves the current `hibernate.default_catalog` configuration property value.
{h-schema}:: resolves the current `hibernate.default_schema` configuration property value.
{h-domain}:: resolves the current `hibernate.default_catalog` and `hibernate.default_schema` configuration property values (e.g. catalog.schema).

With these placeholders, you can imply the catalog, schema, or both catalog and schema for every native query.

So, when running the following native query:

[source, java, indent=0]
----
@NamedNativeQuery(
    name = "last_30_days_hires",
    query =
        "select * " +
        "from {h-domain}person " +
        "where age(hired_on) < '30 days'",
    resultClass = Person.class
)
----

Hibernate is going to resolve the `{h-domain}` placeholder according to the values of the default catalog and schema:

[source, sql, indent=0]
----
SELECT *
FROM   crm.analytics.person
WHERE  age(hired_on) < '30 days'
----

[[sql-synchronization]]
=== Synchronization spaces

Hibernate cannot generally infer the tables affected by an arbitrary SQL string.
`NativeQuery.addSynchronizedEntityClass()`, `addSynchronizedEntityName()`, and `addSynchronizedQuerySpace()` declare the affected query spaces.
These declarations help Hibernate determine whether pending changes require flushing and which spaces are relevant to query caching.
For the flush behavior of native queries, see <<flushing-auto-native,automatic flushing of native SQL queries>>.
For caching, see <<caching-query>>.

[[sql-native-mutations]]
=== Native mutations

Use `createNativeStatement()` for a native insert, update, or delete and execute it within a transaction.
Native affected counts describe database rows; they need not have the entity-count semantics of HQL mutations.
Native SQL does not synchronize managed entity instances. See <<query-mutations>> for handling the persistence context.
