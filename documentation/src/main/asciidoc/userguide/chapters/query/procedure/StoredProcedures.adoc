[[stored-procedures]]
== Stored procedures and functions
:example-dir-model: {testing-project-dir}/src/main/java/org/hibernate/testing/orm/domain/userguide
:example-dir-procedure: {core-project-dir}/src/test/java/org/hibernate/orm/test/sql

Stored procedure calls have a different execution model from <<sql,native SQL queries>>.
Use the standard `StoredProcedureQuery` API for portable calls, or Hibernate's `ProcedureCall` for provider-specific features.
The examples below demonstrate database-specific procedure definitions and their invocation.

[[sql-sp]]
=== Creating calls and registering parameters

`EntityHandler.createStoredProcedureQuery()` creates a procedure call.
Register input arguments as `IN`, output values as `OUT`, and arguments with both roles as `INOUT`, specifying each argument's Java type.
Bind input values with `setParameter()` before execution.
Named procedure declarations may supply the parameter registrations in advance.
A procedure may return result sets directly or through `REF_CURSOR` parameters, depending on the database and driver.
Function return values have a separate declaration; see <<procedure-functions>>.
Calls that modify data require a transaction.

[[sql-sp-named-query]]
=== Named procedure calls

[[procedure-results]]
=== Processing results and output values

Process result sets and update counts using `getResultList()`, `hasMoreResults()`, and `getUpdateCount()`;
when processing multiple results, retrieve output parameter values after the results and update counts.
An update count of `-1` indicates that there is no current update count.
A procedure may return multiple results, and its first result need not be a result set.

[[procedure-functions]]
=== Function calls

A database function usually has a return value distinct from its arguments.
The standard `StoredProcedureQuery.registerResultParameter(ReturnType.class)` declares the return parameter of a function call.
Hibernate's `ProcedureCall.markAsFunctionCall()` is a provider-specific alternative.
JDBC call syntax and support for cursor returns depend on the database.
See link:{doc-javadoc-url}org/hibernate/procedure/ProcedureCall.html[`ProcedureCall`] for the available function-call overloads.
These calls are distinct from functions used inside HQL expressions.

[[procedure-resources]]
=== Resource handling

In Jakarta Persistence 4, `StoredProcedureQuery` implements `AutoCloseable`, as does Hibernate's `ProcedureCall`.
Use try-with-resources to release JDBC resources after processing the results and output values.
Explicit cleanup does not require unwrapping the standard procedure query.

[NOTE]
====
Stored procedure queries cannot be paged with `setFirstResult()/setMaxResults()`.

Calls may return multiple result sets and update counts; process them as described in <<procedure-results>>.
`hasMoreResults()` returning `false` may indicate an update count rather than the end of the results.
Processing is complete when there is no result set and `getUpdateCount()` returns `-1`.

For SQL Server, if you can enable `SET NOCOUNT ON` in your procedure it will probably be more efficient, but this is not a requirement.
====
