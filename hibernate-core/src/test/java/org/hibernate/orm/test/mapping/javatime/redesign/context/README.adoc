= Temporal mapping-context verification

This package supplements the seven-type preservation matrix and leaves the legacy
org.hibernate.orm.test.type.temporal suite unchanged. It tests actual mapping roles,
mutable READ_WRITE caches and snapshots, not a new temporal policy.

== Running

[source,shell]
----
./gradlew :hibernate-core:test \
  --tests 'org.hibernate.orm.test.mapping.javatime.redesign.context.*' \
  -Pdb=h2 -Ptest.threads=1
----

Use postgresql or oracle for the live aggregate/platform cases. The representative
non-UTC configuration additionally uses temporalTestJvmTimeZone=America/Denver and
temporalTestSessionTimeZone=Asia/Tokyo. These select the forked JVM's initial timezone
and connection initialization SQL; they do not request domain adjustment.
Each test parameterizes metadata access enabled/disabled internally.

ContextScope provisions only fixture-owned schema objects separately, disables
runtime schema actions and uses a lazy guarded provider through metadata-disabled
SessionFactory construction. It asserts every attempted acquisition, including
attempts whose exceptions boot code catches. The guard opens before real operations.
No DialectContext supplies a previously initialized Dialect.

The configured database version is an input when metadata access is disabled.
Defaults deliberately match the pinned local environment: H2 2.5.252, PostgreSQL
18.6 and Oracle 23.26.1. An explicitly configured
jakarta.persistence.database-product-version takes precedence. In particular,
H2Dialect's conservative default 2.1.214 cannot establish JSON aggregate support.
These tests do not infer newer capabilities from a failed mapping or obtain a boot
connection to discover them. Unsupported aggregate families are visible skips, not
passing negative tests. SQL Server live verification remains deferred.

A test TypeContributor selects the existing matched plain UTC timestamp descriptor
on direct-enabled handling. This keeps COLUMN collection keys valid on Oracle,
which disallows its zoned timestamp type as a set key. It does not select a generic
TIMESTAMP handler or redefine the production default. Default INLINE native/baseline
constraints remain enforced, including PostgreSQL offset loss rejection.

== Coverage and interpretation

* TemporalContextLifecycleTests: mutable scalar INLINE/COLUMN contexts, reused and
nested member declarations, generic superclass COLUMN/copy isolation, source-value
non-mutation, precision-transition cache origins, real changes and unchanged flushes.
* TemporalCollectionLifecycleTests: independent entity/collection cache hits, set
content, list ordering, bag multiplicity, no-op flush, real add/remove/replace and
cache update/invalidation observed before explicit eviction can hide stale entries.
* TemporalRoleExclusionTests: explicit ID/version/embedded-ID/map/array/embedding
rejections, broader-default skipping and runtime legacy controls. Map keys and values
are both offset-bearing; plain TIMESTAMP keys avoid Oracle's physical key restriction.
Excluded array/map results are compared with equivalent mappings without defaults,
rather than being given the new scalar preservation guarantee.
* TemporalAggregateExclusionTests: real STRUCT/JSON/XML boot and live controls,
explicit NONE/target/INLINE/COLUMN/auxiliary rejections, nested members and ordinary
reuse beside aggregate use. Models assert absence of both adjustment converters and
contextual composites in excluded members, with included reuse remaining contextual.
* TemporalConverterContextTests: explicit/auto-applied active conflicts for scalar,
set/list/bag and INLINE/COLUMN, disabled controls, valid NONE controls, and rejection
of unsupported explicit whole-value COLUMN conversion rather than silent discard.
An excluded map also proves that skipping defaults retains its active user converter.
NONE does not promise arbitrary converter/COLUMN compatibility.
* TemporalCustomCompositeContextTests: ordinary registration, explicit temporal
composite subclass, copies and otherwise eligible immutable reference-cache control.

The cache provider is the existing CachingRegionFactory test implementation with
mutable READ_WRITE entries; query cache is disabled. SQL inspection and statistics
measure isolated intervals. Each transaction opens a fresh session. A second-level
entity hit is not counted as a collection hit. An entity/collection cache control
must report actual hits and omit the corresponding row selects. Mutation checks
exclude setup and require no mutation DML; real changes must survive a JDBC-backed
read and fresh cache assembly. Earlier detached source collections remain unchanged.

Cache precision retains its approved origin boundary: supplied fractional values
may survive write-populated entries while load-populated entries use extracted
precision. Each origin resolves regional offsets at its own instant. COLUMN
ZonedDateTime reconstructs fixed-offset identity before explicit adjustment.
No canonicalization, extra readback, ambient/global adjustment or equality redesign
is introduced. Existing immutable cache and legacy reference-cache tests remain
separate regression controls.

Aggregate families unsupported by the configured Dialect remain explicit skips.
The seven-type matrix supplies separate descriptor/range/timezone coverage.

== Declaration and legacy compatibility tests

TemporalScopeDeclarationTests covers active field/getter access, declaring type and
exact package lookup, inherited members, invalid targets and zone identity.
TemporalModuleDeclarationTests compiles temporary module-info/package-info fixtures
using the test JDK's JavaCompiler. Each realm has its own loader/layer identity;
identically named classes/modules intentionally carry different defaults. Automatic
and unnamed modules provide controls. A full JDK is required; no fixture changes
JVM timezone or mutates annotations.

TemporalLegacyDeclarationTests and TemporalPrecedenceRegressionTests exercise local
legacy/new selector combinations, independently selected global contributions,
fully replaced versus uncovered global policies and ineligible nearer defaults.
TemporalDeclarationLogTests isolates the explicit-setting deprecation report per
bootstrap, including overridden, unused and rejected policies. These declaration
suites use H2 with metadata enabled and guarded disabled bootstrap.

TemporalColumnLayoutTests checks all matching tuple operation flags and rejects
mismatches in either direction, including component overrides. Independent JDBC
seeds and fresh uncached sessions establish update-only/read-only results.
TemporalColumnNamingTests compares hand-checked identifiers and quoting across the
new selector, legacy COLUMN alias and direct-disabled legacy handling; quoted
physical names also undergo live DDL/read/schema validation.
TemporalNativeConstraintTests distinguishes preserving plain handling from a retained
NATIVE constraint and exercises its scoped replacement through live reads. Naming
and native cases run on H2, PostgreSQL and Oracle; SQL Server remains deferred.

TemporalConverterRelationalTests checks preservation of an active application's
relational Java type with its resolved JdbcType. It covers explicit/auto converters,
identity and differing carriers, non-temporal domains converted to Java Time,
precision boundaries, and retained rejection of unknown pairs. The converter still
owns domain conversion; its presence alone does not establish JDBC preservation.

TemporalDynamicModelTests uses the original dynamic XML composite-ID mapping beside
a real Java temporal mapping, including JDBC persist/load and both metadata modes.
TemporalRegistryContextTests checks standalone null-registry defaults and supplied
registry true/false isolation. Its SQL Server descriptor checks are model-only;
SQL Server live verification remains deferred.

== Internal system-period compatibility

`TemporalSystemPeriodTests` explicitly selects `temporal_preservation=false` and covers Hibernate-owned row-start/end mappings separately
from application Java Time attributes. It exercises both emulated storage strategies,
entity and collection history, configured suppliers and server generation, copies,
precision diagnostics and bootstrap with JDBC metadata access disabled. The ordinary
Instant/raw TIMESTAMP negative case separately checks enabled preservation.
Legacy temporal/conversion tests are unchanged.

Run with aligned JVM/session zones, for example
`-PtemporalTestJvmTimeZone=America/Denver -PtemporalTestSessionTimeZone=America/Denver`,
and separately with UTC. The raw timestamp assertions intentionally verify the existing
local-clock encoding. These tests do not request UTC normalization or a migration of
historical data. Mismatched JDBC Calendar/server-clock behavior and DST ambiguity remain
limitations of that legacy protocol; enabling preservation requires migration analysis of historical data. SQL Server live verification is deferred.
The descriptor-isolation control also verifies that the previous internal period
handling can coexist with the new application descriptor and custom contributions.


== Preservation mode and internal temporal roles

TemporalPreservationModeTests, TemporalPreservingNamedVersionTests and
TemporalPreservingVersionCacheTests exercise the new temporal_preservation setting,
its deprecated alias, version mapping views, generated tokens, optimistic locking and
cache/dirty-checking behavior. TemporalPreservingPeriodTests checks exact history
boundaries and collection history with UTC-encoded H2 periods, including a JDBC timezone
mismatch. Run these with UTC and non-UTC temporalTestJvmTimeZone profiles.

TemporalSystemPeriodTests verifies the disabled-mode compatibility contract.
TemporalPreservingPeriodTests verifies the default-enabled protocol; their different
raw-field expectations intentionally cover the two selected modes.

== Query and callable boundaries

`TemporalColumnQueryTests` checks existing SQL tuple semantics for OffsetTime,
OffsetDateTime and ZonedDateTime COLUMN mappings. Equal primary values with different
offsets remain distinct unless an explicit adjustment makes both components equal.
The fixtures include offset seconds and microsecond precision. Scalar Criteria literals
cannot represent these composite values; a whole-value parameter is the supported
alternative. Bulk assignments are checked in fresh sessions and against physical
primary/offset columns.

`TemporalNativeQueryTests` passes the resolved attribute type explicitly for native
parameters and scalar results, with two independent adjustment targets. A class-only
scalar follows ordinary driver interpretation and does not inherit an attribute's
adjustment from its SQL alias. The Instant control uses the established UTC fallback.

`TemporalCallableQueryTests` exercises live ORM calls and function returns. Oracle
covers IN/OUT/INOUT, PostgreSQL covers IN plus its unsupported timetz OUT/INOUT boundary,
and composite callable parameters/returns fail before JDBC binding. The optional
`hibernate.test.temporal.observe_callable` test-provider setting records actual JDBC
method names and parameter positions/names. Named ORM registration adapted to JDBC
positions is reported separately from actual named JDBC calls. Metadata-disabled
bootstrap still forbids connection acquisition; normal runtime calls may connect.
Provider-specific cases are deliberately inapplicable on other databases.

The function fixture uses the same plain TIMESTAMP UTC carrier as its explicit
mapping-aware type. Its SQL signature must not introduce an implicit conversion to
TIMESTAMP WITH TIME ZONE. Native SQL/schema compatibility remains the caller's
responsibility. Physical tuple checks read TIME and TIME WITH TIME ZONE in their own
JDBC forms, avoiding session-dependent casts through Timestamp.

These sequential matrices opt into `hibernate.test.temporal.reuse_connection` to
retain at most one idle connection per test provider and close it at registry shutdown.
This limits Oracle Free connection churn. Existing connection-isolation tests keep
physical acquisition/close behavior unchanged.

== Custom descriptor contracts

`TemporalDescriptorAssessmentTests` verifies optional Java-side requirements, pair-aware JDBC
reports, conservative replacement recognition, inherited explicit contracts, precedence and
recursion diagnostics. Its PostgreSQL/Oracle Dialects are offline dispatch controls, not live
driver evidence. Reports are assessed per configured instance without a global result cache.

`TemporalDescriptorMappingTests` executes H2 custom pairs for Instant and an immutable date
value, including raw columns, fresh reads, nulls, collections, predicates, bulk assignment,
converter relational types and explicit function results. Both metadata modes are exercised;
legacy-disabled and older TemporalJavaType controls forbid new callback invocation. Separate
factories contribute differently configured instances of the same descriptor class.

Run these with `--tests '*TemporalDescriptor*Tests' -Pdb=h2`, first with
`-PtemporalTestJvmTimeZone=UTC -PtemporalTestSessionTimeZone=UTC`, then with
`-PtemporalTestJvmTimeZone=America/Denver -PtemporalTestSessionTimeZone=Asia/Tokyo
-PtemporalTestJdbcTimeZone=Europe/Paris`. These tests supplement the existing adjustment,
COLUMN, converter and query/callable regressions; they do not replace legacy conversion coverage.
SQL Server live verification remains deferred.

== Provider periods and migration handoffs

`TemporalProviderPeriodTests` exercises stock enabled period handling on H2 and PostgreSQL
(SINGLE_TABLE and HISTORY_TABLE) and Oracle (HISTORY_TABLE). It checks both physical bounds,
NULL open ends, entity values and ordered collection membership immediately before and at each
boundary. Fixed suppliers cover seasonal values and distinct instants in a DST fold. Server
boundaries are checked against a separate physical connection's database-clock samples, with
fresh monitor transactions and at most one storage tick of rounding tolerance.

Writer, monitor and reader connections remain simultaneously open and have distinct database
session identities. Session initialization is checked on each. Schema provisioning is separate
from metadata-disabled runtime bootstrap, whose connection provider rejects every attempted
boot acquisition. These tests do not treat a preservation report as a server-producer capability.

Run the provider-period class with `-Pdb=h2`, `-Pdb=postgresql`, or `-Pdb=oracle`; use
`-Ptest.threads=1` for the live PostgreSQL/Oracle matrices. The core environmental profiles are:

* `-PtemporalTestJvmTimeZone=UTC -PtemporalTestSessionTimeZone=UTC` (JDBC timezone unset).
* `-PtemporalTestJvmTimeZone=America/Denver -PtemporalTestSessionTimeZone=Asia/Tokyo
  -PtemporalTestJdbcTimeZone=Europe/Paris`.
* HISTORY_TABLE controls additionally use aligned Denver JVM/session, JDBC timezone unset.

`TemporalHandoffProcess` launches a test-only main on the existing test runtime classpath.
It never invokes a nested build. Enabled period writer/reader phases use separate JVMs:
Denver/Tokyo/Paris becomes Tokyo/Denver/Paris (JVM/session/JDBC). Each child asserts its actual
JVM zone before bootstrapping. Parent system properties such as `user.timezone` must not be
copied over the explicit child JVM configuration. H2 uses a fixture-owned file database.
Only owned schema objects are created/dropped. Connection configuration is temporary and removed
in finally; credential-free manifests and clock/profile evidence are included in test output.
Failed child logs remain in the reported temporary directory.

`TemporalMigrationHandoffTests` uses explicit `temporal_preservation=false` source factories
and independent enabled targets. The source protocol is pinned to the recorded
321b4ff81f217149f612878129a31cca599e6ab8 baseline and guarded by raw-field/source-reader checks;
the executing revision is recorded separately. These tests do not execute an old Hibernate
release or certify every historical application encoding.

The bounded fixtures cover retained PostgreSQL zoned Instant/version/period storage, retained
local versions, explicit UTC-to-local version conversion, local-to-UTC period conversion,
the UTC period control, Oracle normalized-to-native versions, and unsupported target rejection.
The retained PostgreSQL Instant version explicitly selects TimestampUtcAsOffsetDateTimeJdbcType;
it does not imply that the default target Instant DDL always matches old schemas. Conversion
uses reviewed SQL only for owned modern-date fixtures, with an unchanged negative copy.
Legacy fold ambiguity and ancient-calendar conversion remain outside that SQL domain.

Version checks distinguish Java token identity, old-token SQL predicates, detached merge,
generated-token reload, stale operations and fresh deletion. An H2 cache cutover populates and
invalidates source cache entries before the target's JDBC-backed read. Period handoffs compare
all old bounds and historical reads, then update/delete through the final producer. Explicit
schema validation is supplemented by actual history-column type/precision/nullability checks;
a schema-validation pass alone is not data-migration evidence.

Migration children use the profile's unchanged source/target timezones, independently of the
parent test environment. Most cells close both factories sequentially in one child; designated
cells separate writer and target JVMs. This keeps timezone changes and migration changes as
independent axes. Runtime bootstrap covers metadata enabled and disabled. There is no automatic
migration on boot and no production migration-script generator in these fixtures.

`TemporalCollectionHistoryRepairTests` and `HistoryCollectionDecomposerTest` cover graph history
removal/value changes, clear/recreate, ordering, snapshot fallback, explicit history dependencies,
completion timing and rollback. Existing legacy tests remain unchanged.
`TemporalLegacyHistoryBatchTests` covers the HHH-21102 legacy batching repair with exact current
and historical list contents, batch sizes 0/1/5, and failure/rollback controls. These legacy
controls complement the graph regressions; neither substitutes for the other.
SQL Server live/native-period verification remains deferred.

== CI environment and subprocess ownership

Context fixtures discover the database version during setup, outside the guarded
runtime bootstrap. Metadata-disabled factories receive that version as an explicit
input and still assert zero bootstrap connection acquisitions. Explicit synthetic
version inputs remain available for offline bootstrap controls; they are not live
provider evidence.

Handoff processes receive connection settings after the parent resolves Gradle's
worker placeholders. Writer, reader and cleanup therefore retain the same database
assignment even though the children have different process parents. Keep at least
two test workers when verifying this isolation on a provider configured with worker
namespaces; a single-worker pass cannot establish parallel safety. The H2 handoffs
retain their private file-backed databases.

Provider selection recognizes Dialect subclasses, including PostgreSQL's EDB family.
Fixture eligibility is evaluated outside expected-mapping-failure assertions. These
gates describe the fixture matrix and do not declare additional production guarantees.
